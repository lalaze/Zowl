# Android 自动采集只读支付页，停用通知解析

状态：已实现，待真机验证。日期：2026-11-16。

## 背景

ADR-0006 的通知监听与 ADR-0008 的支付页（无障碍）采集是两个互斥的设备模式。通知解析要为每个来源维护一套正则，支付应用改文案就会漏记，也无法覆盖只有页面没有通知的付款。用户决定不再维护通知解析，全部走无障碍。

## 决定

- Android 删除通知监听服务、支付宝/微信/招商银行三个通知解析策略、监听健康检查与告警、开机广播接收器和 `RECEIVE_BOOT_COMPLETED` 权限，不再申请通知使用权。采集模式开关随之取消，总开关开启即为支付页采集。
- 招商银行不再是采集来源：它只有通知解析，没有支付页解析器。
- 支付页采集的范围不变：ADR-0008 的节点读取、ADR-0010 的本机 OCR 兜底、checkout 会话、`payment_page_capture` 来源与独立的 `autoPostPaymentPages` 授权都保持原样。
- 服务端不改。已登记的通知解析器身份、按平台的通知自动入账授权、`notification_capture` 来源继续保留，用于历史候选与账目，以及仍在使用 1.0.4 及更早版本的设备。App 设置页不再展示按平台的通知自动入账开关。
- ADR-0006 中与候选、加密队列、隐私、确认和账单补充有关的边界继续有效；其监听、解析规则与健康告警部分作废。ADR-0008 的“两种互斥模式”作废。

## 代价与已知风险

- 升级后原先使用通知模式的设备必须手动开启 Zowl 无障碍服务，否则不再采集；`autoPostPaymentPages` 默认关闭，原先按平台开启的通知自动入账不会自动沿用。
- Android 13 及以下没有 ADR-0010 的窗口截图能力，支付页读不到文字的应用（已知：部分机型上的微信）在这些设备上没有任何自动采集，此前可退回通知模式。
- 招商银行卡直接扣款不再自动采集，只能手动记账或导入账单。
- 无障碍服务被系统关闭或强制停止后没有主动告警，只能在设置页看到状态。
- 淘宝、拼多多、京东等应用内的支付成功页不在本决定范围内，见 ADR-0012。

## 验证

JVM 单元测试（支付页解析、OCR 门控、队列与错误文案）与 Flutter 测试通过，仪器测试已编译但未在设备上运行。真机需验证：从通知模式升级后的状态与提示、支付宝和微信各至少五笔真实付款、撤销无障碍权限与强制停止后的恢复。
